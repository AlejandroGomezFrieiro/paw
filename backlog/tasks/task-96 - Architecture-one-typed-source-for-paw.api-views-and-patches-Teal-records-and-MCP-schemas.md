## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Goal: one typed Rust struct for each shape that crosses paw.api, the MCP server and the frontends, and the other descriptions made from it. Finding F2 of the architecture review (backlog/docs/designs/architecture-review.md).

Today: views are json! maps (session/tracks.rs track_view, lines 6 to 29, and track_field again in a match); setters read a key into an enum (TrackField) and the value as serde_json::Value; the API converts Lua to serde_json::Value first, so two conversions per call. runtime/lua/paw/types.tl (1781 lines, 146 records) is written by hand. paw-mcp writes its JSON Schemas by hand (tools/write.rs, schema.rs). paw-gui reads the frontend state through 192 string keys.

Change, one branch for each area (tracks first, then clips, devices, lanes, transport, project, then the frontend state):
- #[derive(Serialize)] TrackView and #[derive(Deserialize)] #[serde(deny_unknown_fields)] TrackPatch (Option<Option<T>> or a Patch<T> enum to clear a field); paw.api converts Lua straight to the struct with mlua serde, no serde_json::Value between.
- tools/apidoc.lua makes the Teal records from the structs (as for paw-scene/src/props.rs); the hand records leave types.tl.
- paw-mcp makes its schemas with schemars from the same structs (owner question 3 of the review).
- The frontend state becomes typed structs in paw-proto with generated Teal records; paw-gui reads fields.

Read first: the review, F2; crates/paw-core/src/session/tracks.rs; api/tracks.rs; api/mod.rs (to_lua, changes); tools/apidoc.lua (serde structs, near line 1277); runtime/lua/paw/types.tl; crates/paw-mcp/src/tools/write.rs and schema.rs; .claude/skills/teal and rust-skills.

Keep: the same error texts that Lua or a user sees; nil for absent fields in Lua.
Size: L in all; each area is S or M.
